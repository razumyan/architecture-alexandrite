## Мотивация

Без надлежащей системы мониторинга ошибки и сбои остаются незамеченными. Время для разбора инцендентов
значительно увеличивается. Что может подставить под удар существование бизнесса. Необходимо повысить наблюдаемость
системы, чтобы выявить слабые места, а также процессы требующие незамедлительной перестройки. Кроме того мониторинг
позволяет опреативней реагировать на возникающие проблеммы.

## Выбор подхода к мониторингу

Для отслеживания состояния системы удобней будет воспользоваться принципами RED для всей системы в целом и USE для
сервиса MES, т.к. он выполняет большую алгоритмическую работу связанную с оценкой заказа.

## План действий

1. Повысить наблюдаемость системы
    1. Внедрить Prometheus/Graphana для сбора и непрерывного анализа метрик сервисов
    2. Внедрить логирование API вызовов
    3. Внедрить трейсинг API вызовов на основе OpenTelemery/Jagger
2. Построить строгую очередность на Rabbit MQ в контексте изменения статуса заказа.
    1. Любые изменения статуса заказа должны проходить через очередь с подтверждением обработки.
    2. Выявить точки отказа системы, задержки в обработке заказов.
3. Внедрить систему алертинга для следующих показателей
    1. Появление записей `dead-letter-exchange` в контексте статуса заказа, отправлять письмо о необходимости ручного
       вмешательства в обработку, т.к. система "потеряла" заказ
    2. Темп заполнения дискового пространства (S3/DB) говорит, что оно закончится в течение 7 дней. Необходимо отправить
       сообщение, с предупреждением.
    3. Загрузка CPU превысила 75% и не снижается более 30 минут. Необходимо отправить сообщение дежурным.
    4. Среднее время отклика системы превысило 10 сек. Отправить сообщение дежурному.
    5. Процент отказов API превышает 10%. Необходимо отправить сообщение дежурным.
    6. Процент `in-flight` сообщений превысил 50%. Необходимо отправить сообщение дежурным.
    7. Трафик перешел порог 70% от пропускной способности сети и продолжает расти. Необходимо отправить письмо.
    8. Трафик резко вырос (в течение часа) до 50% от пропускной способности сети и продолжает расти. Необходимо
       отправить сообщение дежурному.
